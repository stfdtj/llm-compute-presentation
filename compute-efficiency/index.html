What Limits Our Computing Speed?

A processor has to load data and do calculations. Depending on the job, either one can be the bottleneck. Roofline analysis tells us which one — for a given computation, on given hardware.

AI = FLOPs ÷ Bytes

How much computing happens per byte of data moved.

DeepSeek V4.1 Flash's Query Low-Rank Projection uses two matrices: [5120, 1280] and [1280, 32768] — a token's hidden vector is compressed, then expanded back out into 64 attention-head queries.

FLOPs = 2 × Tokens × (5120×1280 + 1280×32768)

Memory traffic (simplified BF16 model): weights are read once per batch; the input, the intermediate result, and the output each scale with the number of tokens.

Scope: only these two linear layers. RMSNorm and the rest of Attention are excluded from this teaching example.

How Much Computing Power Are We Actually Using?

MFU compares the model's useful training computation per second with the hardware's theoretical peak computing power.

MFU = Useful Model FLOPs/s ÷ Hardware Peak FLOPs/s × 100%

An explicitly hypothetical, illustrative training example — not a measurement of DeepSeek V4.1 Flash or any specific hardware.

The equation above already shows every step with real numbers substituted in. One extra note on where "Training FLOPs per token" would come from for a real model:

For a Mixture-of-Experts model like DeepSeek V4.1 Flash, only a small fraction of stored parameters are actually used by any one token — applying the common "6 × total parameters" rule of thumb directly would overstate real training cost. This example deliberately keeps that complication out of the headline number and uses clearly hypothetical figures instead; see README.md for a worked MoE active-vs-total comparison.
