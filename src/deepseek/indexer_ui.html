评分范围、缓存与计算口径

S 是已缓存的全局条目数，C 是实际参与评分的行数，Top-K 512 只是选取上限。参考 inference/model.py 先对可用 Index Key 缓存计算分数，再进行因果 / 候选掩码；不能把 Top-K 数或候选池上限直接代入该实现的评分工作量。

Layer 20 同时建立分层候选池（最多 2048 × 8 = 16384 个位置）；后续 Reindex 在候选范围内选择。报告中的候选域评分优化与参考代码的先评分、后掩码应区分。Indexer 与 Main Attention 各有自己的 Query；Head Weights 来自当前 X 的可学习投影，并非固定常量或 MoE 路由权重。

计算面板复用统一逐步账本，A单Token与B理论训练分别计算。数值主例是Full源层，架构按钮不改变场景条件。主损失在Top-K处没有普通连续梯度；给定额外dScore的评分VJP单列，训练目标来源Unknown。只有 Full 层在新压缩条目完成时追加 Index Key，ratio=2 的未完成组不会新增条目。
