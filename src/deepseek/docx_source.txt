Chapter 2 — Query and Shared KV Projection
2.1 Low-rank Query construction
Purpose: Produce a separate query vector for every head while reducing projection parameters.
Inputs: X∈RT×5120.
Learnable parameters: AQ∈R5120×1280, BQ∈R1280×32768, and the Query RMSNorm scale vector.
Formula: The calculation is
Qrraw=XAQ,Qr=RMSNormq(Qrraw),Qflat=QrBQ
Shape calculation: The dimensions are
T×5120)(5120×1280)→(T×1280);(T×1280)(1280×32768)→(T×32768
Explanation: The first projection produces a bottleneck representation. Normalization controls its feature scale before the second projection expands it into all Query heads. This is a low-rank architectural factorization, rather than a standard LoRA fine-tuning adapter added to a frozen dense weight.
Output: Qr also feeds the sparse indexer when that layer computes index scores.
64·512=32768,Q=reshape(Qflat,T,64,512)
A reshape changes organization without adding parameters or changing the number of elements. Different heads receive different feature slices. PyTorch Linear stores the transpose of the matrices shown here: output features precede input features.
2.2 RMSNorm in detail
Purpose: Normalize each row’s root mean square without subtracting its mean.
Inputs: A row x∈Rd and a positive stability constant ϵ.
Learnable parameters: A feature-wise scale γ∈Rd; there is no additive offset in the local RMSNorm class.
Formula: The calculation is
RMSNorm(x)=x1di=1dxi2+ϵ⊙γ
Shape calculation: The dimensions are
T×d)⟶(T×d
Explanation: Square each component, average over the last dimension, add epsilon, take an inverse square root, and multiply every component by that row’s inverse RMS and its learned feature scale. The local code computes these statistics in floating point with 32-bit precision, then returns the original activation dtype.
Output: A normalized row with the same feature count.
vpq=11280i=11280(Qr,p,iraw)2,Qr,p,i=γiqQr,p,irawvpq+10-20
There are no learned projection entries or checkpoint activations in the supplied material, so the actual token activations cannot be computed. The expression above gives their full row-wise calculation without inventing numbers. The class constructor’s fallback epsilon differs from the configuration; the attention and block instances explicitly receive norm_eps.
2.3 Shared KV construction
Purpose: Create one compact representation used as both the attention key and the value.
Inputs: X∈RT×5120.
Learnable parameters: WKV∈R5120×512 and a KV RMSNorm scale γKV∈R512.
Formula: The calculation is
Lraw=XWKV,L=RMSNormKV(Lraw)
Shape calculation: The dimensions are
T×5120)(5120×512)→(T×512
Explanation: All Query heads compare with the same latent sequence. The model does not construct separate head-specific keys and values inside this attention module. Broadcasting the shared latent for computation does not require storing a separate copy for every head.
Output: L is the unrotated shared KV latent.
vpKV=1512i=1512(Lp,iraw)2,Lp,i=γiKVLp,irawvpKV+10-20
The KV tensor remains T×512, rather than T×64×512. Replacing standard independent projections with this shared representation is a model-specific assumption, not a rule for all Transformers.
2.4 Parameter-count correction and projection tradeoff
NQ,dense=5120·32768=167772160
NQ,factorized=5120·1280+1280·32768=48496640

Chapter 3 — Rotary Positional Embedding (RoPE)
3.1 Selected dimensions and angles
RoPE encodes position by rotating feature pairs. This local implementation rotates adjacent pairs within the last 64 features of each Query head and each shared KV latent. The first 448 features are unchanged. For zero-based feature indexing, the rotated range begins at feature 448.
dR=64,dh-dR=448,i∈{0,…,31}
ωi=b-2i/64,θp,i=pωi,b=10000
This base-frequency expression applies directly to layers 0 and 1, whose compression ratio is zero. Position zero produces identity rotations. A different pair index gives a different angular frequency, letting the positional features operate at different distance scales.
3.2 Pair rotation and the full rotary matrix
Purpose: Insert position information into the selected feature subspace.
Inputs: One adjacent feature pair u,vT, token position p, and pair index i.
Learnable parameters: No learned rotation matrix; frequencies come from configuration.
Formula: The calculation is
u'v'=R(θp,i)uv,R(θ)=cosθ-sinθsinθcosθ
Shape calculation: The dimensions are
2×2)(2×1)→(2×1
Explanation: The two features behave like the real and imaginary parts of a complex number. Multiplying by a unit complex exponential rotates them and preserves their Euclidean norm. The code explicitly reshapes adjacent features into complex pairs.
Output: Rotated pairs, assembled back into the 64-feature tail.
Rp=diag(R(θp,0),R(θp,1),…,R(θp,31))∈R64×64
Rp=cosθp,0-sinθp,000⋯sinθp,0cosθp,000⋯00cosθp,1-sinθp,1⋯00sinθp,1cosθp,1⋯⋮⋮⋮⋮⋱
The source image uses a schematic final block for the last pair. The block-diagonal equation explicitly includes all 32 pair blocks and resolves that shorthand. The small column-vector formula above defines the rotation; row-vector storage applies its transpose on the right.
R~p=diag(I448,Rp),Qp,h,:'=Qp,h,:R~pT,Lp,:'=Lp,:R~pT
Q'∈RT×64×512,L'∈RT×512
3.3 Why the dot product contains relative position
(Rpq)T(Rjk)=qTRpTRjk=qTRj-pk
For a fixed frequency schedule, the rotation portion of similarity depends on the difference between key and query positions. The unrotated features still contribute content similarity. This is the relative-position mechanism described by RoFormer; the example below is a pedagogical pair, not a checkpoint activation. Reference: https://arxiv.org/abs/2104.09864.
q=k=10,qTk=1,(R(pω)q)T(R(jω)k)=cos((j-p)ω)
ω0=1:cos(0)=1,cos(1)≈0.5403,cos(2)≈-0.4161
Without rotation, these identical content pairs score identically at every distance. With rotation, their contribution changes with distance. No claim is made that a complete learned attention score must decrease monotonically with distance.
3.4 Compressed-attention frequency schedule
Code inspection shows that a compression-enabled layer uses compress_rope_theta for all of its Query, local KV, compressed KV, and indexer rotations, with YaRN enabled by original_seq_len. Thus the source’s base of ten thousand must not be applied unchanged to the layer-2 example.
b=160000,L0=65536,f=16,βfast=32,βslow=1
c(β)=64ln(L0/(2πβ))2lnb,l=max(⌊c(32)⌋,0),u=min(⌈c(1)⌉,63)
ρi=clipi-lmax(u-l,10-3)01,ω^i=(1-ρi)ωi+ρiωi16
θp,i=pω^i
These equations follow precompute_freqs_cis, including its bounds and interpolation. Low pair indices keep the base frequency; high pair indices can be slowed for context extension. Partial rotation reduces direct positional-rotation work while leaving most features unrotated; it does not remove positional effects propagated by previous layers.

Chapter 4 — Self-Attention Computation
4.1 Similarity for one head and all heads
Purpose: Measure how strongly a Query matches each accessible key representation.
Inputs: A head-specific Query Qh' and the shared rotated latent L'.
Learnable parameters: The Query and KV projections already introduced; no extra similarity matrix.
Formula: The calculation is
Sh=Qh'(L')Tdh,dh=512
Shape calculation: The dimensions are

5.6 Cross-layer reuse and later candidate filtering
A positive compression ratio does not mean every layer computes its own compressed KV or indexer. Chapter 7 — Hyper-Connection (HC)
7.1 Residual streams and dynamic coefficients
A residual stream carries each token’s evolving features between sublayers: identity information, contextual features, and representations useful for prediction. These are interpretations of learned features, not fixed named fields in a tensor. Hyper-Connections maintain four parallel streams and learn how to collapse, update, and mix them.
R∈RT×4×5120,a,b∈RT×4,Amix∈RT×4×4
Here a denotes pre-mix collapse coefficients, b denotes post-mix broadcast coefficients, and Amix mixes the residual copies. These are token-dependent intermediates computed from learned parameters; they are not independent fixed learned coefficients for every token.

Chapter 11 — Engram — N-gram Memory Lookup and Gated Residual Injection
11.1 Architectural role and execution workflow
Engram supplies learned memory features selected by short, ordered token sequences. It forms a separate branch from the normal Transformer block: token IDs determine memory addresses, while the current Hyper-Connection residual stream determines how strongly the retrieved Value is injected. The configured injections occur immediately before zero-based layers 1 and 14, preserving the four-copy residual shape. The updated residual then enters the existing Attention → HC → MoE → HC calculations in Chapters 2–10.
Attention builds context-dependent interactions between token positions using projected activations, positional transformations, and normalized attention scores. Engram instead uses deterministic N-gram hashes to retrieve learned table rows and applies a separate sigmoid gate for each residual copy; it does not compute an attention distribution over earlier token positions. MoE selects feed-forward experts using a router applied to hidden activations. Engram selects memory rows using token sequences rather than selecting experts. These mechanisms complement one another: memory lookup contributes features before Attention, and the usual context mixing and expert transformations follow.
Workflow: token IDs → compressed token IDs and causal N-gram construction → layer-specific hashing → embedding lookup and dequantization → Key/Value projection → residual-dependent gating → additive residual update. The worked example remains “it is raining”; all original formulas, tables, assumptions about three illustrative token rows, and tokenizer limitations are retained in Sections 11.2–11.9.
Precomputation and execution timing: Transformer.forward calls NgramHashState before the ordinary token embedding lookup and before the backbone loop. Hash addresses for both Engram layers can therefore be computed in advance for the available input chunk: they depend on token IDs, the compressed token map, layer-specific hashing settings, and available causal history, not on hidden activations. This does not precompute the gated residual updates. Each Engram module retrieves and projects its own memory features when its designated layer is reached, then computes its gates from that layer’s current residual stream. The two injections use different residual states and separate learned parameters. During decoding, only available tokens and cached preceding context can be hashed; unknown future tokens are not precomputed.

11.4 Step A — N-gram construction, padding, and hashing
An N-gram is an ordered group of consecutive tokens ending at the current position. This Engram hashes bigrams, trigrams, and four-grams; it does not add a unigram lookup column. No random values are represented as checkpoint outputs.
