先认识问题

模型生成一个词之前，需要“回看”哪些内容？

Token（文本单元）可以是一个字、词或词的一部分。Attention（注意力）让当前 token 从历史内容里找出有用的信息。Decode（逐个生成）每次生成一个新 token，再把它加入历史；生成 1024 个 token，需要连续做 1024 步。

① 需要做多少计算？

FLOPs（浮点运算次数）数的是计算总量。一次乘法或加法通常各算 1 次；它没有“每秒”的含义。下方比较六种组织注意力的方式。

② 怎样比较？

先固定相同输入，再算每一步的运算量并求和。FLOPs 加速比 = MHA 计算量 ÷ 当前架构计算量。MHA 是普通多头注意力，作为对照。

③ 数字能说明什么？

比值 2× 表示在声明范围内计算量减半。运行速度还受数据搬运影响；下一页用 Roofline 检查两种限制。

认识六种架构与图表中的术语

MHA（Multi-Head Attention，多头注意力）；GQA（Grouped-Query Attention，分组查询注意力，共享 Key/Value）；MLA（Multi-head Latent Attention，多头潜在注意力，压缩历史表示）；SWA（Sliding Window Attention，滑动窗口注意力，只回看附近位置）；MSA（这里指 Mini-Sparse Attention，以块为单位选择部分历史）；GDA（Gated Delta Attention，门控 Delta 注意力，用递归状态保存历史信息）。

Query / Key / Value（查询 / 索引 / 内容）用来匹配并汇总历史；KV Cache（键值缓存）存历史表示，避免重复生成它们。Projection（投影）改变表示维度；Core（核心）匹配并汇总历史；Extra（附加）指索引等其他已计运算。图中 S 是已有历史长度，G 是将要生成的 token 数，H 是注意力头数。“每层”指模型里的一个注意力模块，不能当作整个模型。

四种减少量 / 加速比，分别说明什么？

FLOPs Reduction = 1 − 当前 FLOPs / MHA FLOPs，表示计算量减少的百分比；FLOPs Speedup = MHA FLOPs / 当前 FLOPs，表示理论计算量比值。Roofline Speedup = MHA 理想时间下界 / 当前理想时间下界。Measured Speedup = MHA 实测时间 / 当前实测时间，必须测量相同范围和运行条件。四者不能互相替代。

EXPERIMENT 02 / HBM ROOFLINE

计算少了，为什么未必更快？

Roofline（屋顶线模型）分析一个任务更可能卡在计算，还是卡在数据搬运。FLOPs 更少，程序也未必按同样比例变快。

1 · 先认识两种限制

算力：每秒能算多少？

Peak Compute（理论算力峰值）是芯片最快的计算速度，单位 FLOP/s。Compute-bound（算力限制）像厨师已经忙不过来，再加快送菜也未必有用。

带宽：每秒能送多少数据？

HBM（高带宽显存）保存权重和历史数据。Bandwidth（带宽）是每秒最多搬运的字节数。Memory-bound（带宽限制）像厨师在等食材；只减少计算，未必缩短等待。

计算密度：每字节做多少计算？

Arithmetic Intensity（计算密度，记作 AI，与“人工智能”缩写无关）= FLOPs ÷ Bytes Moved（搬运总字节）。每搬运 1 字节，能完成多少次浮点运算？这个比值把计算和搬运联系起来。

4 · 如何解读结果？

带宽限制时，只减少 FLOPs 而不减少搬运量，时间下界可能保持不变；算力限制时，只增加带宽而不改变计算量，也可能无效。比较两种 Attention，要同时看 FLOPs 和 Bytes Moved。

Roofline 是理论性能上界 / 时间下界。真实运行还有启动、串行阶段、算子效率和通信等开销；本页用一个 Tensor Core 峰值近似不同算子，且访存是假设模型，不能把这些结果称作硬件实测。区间合并下界可能比各步下界相加更宽松。

EXPERIMENT 03 / TRAINING ONLY
训练吞吐量，离理论峰值还有多远？


MFU = Model FLOPs Utilization（模型浮点运算利用率）。它衡量训练中模型计算吞吐量占硬件理论峰值的比例，帮助判断训练系统的计算效率。


1 · 先分清三个概念


FLOPs 是工作量
模型训练一个 token 需要多少浮点运算？包括 Forward（前向，产生预测）和 Backward（反向，计算梯度）。理论工作量可以从模型架构推导。


FLOP/s 是速度
每秒完成多少模型运算 = 每 token 理论工作量 × 全设备实测 Tokens/s（每秒训练 token 数）。真实吞吐量通常来自训练日志或计时。


MFU 是比例
把模型运算速度除以全部设备的理论峰值。它不是模型预测准确率，也不是直接测得的 GPU / NPU 忙碌百分比；没有真实训练速度，就没有真实 MFU。


同一模型、精度与计数口径下，MFU 越高通常表示越接近硬件理论算力。但训练质量还取决于数据、模型和优化方法，不能用 MFU 判断学得好不好。


2 · 用简单数字试算
全部为教学假设数据

4 · 如何解读 MFU？
为什么常常不到 100%？
数据准备与传输、显存读取、设备间通信、Kernel Launch（启动计算内核）和算子效率都会占时间。同样的 token 数用时增加，Tokens/s 变小，MFU 随之降低。
算得更少，会怎样？
工作量减少可能让训练更快，但 MFU 看的是“工作量 × 速度”。例如本示例计算量减半、Tokens/s 翻倍，MFU 不变；若速度只提高 50%，MFU 反而下降。
它与 Roofline 有何关系？
两者都用硬件理论上限做参照。Roofline 结合搬运量分析任务受什么限制；训练 MFU 需要实测吞吐量，汇总整个训练系统达到峰值的多少。本页 Roofline 估计并不能代替训练测量。


Decode 与 Training（训练）不能混用。Attention 页面计算单层、逐个生成的前向运算；训练还涉及全模型、前向 + 反向和批量序列。当前单层 Decode FLOPs 不能直接作为 Training FLOPs/token，也不能由理论 Decode 时间下界推出真实训练 MFU。


进阶：模型 FLOPs、MoE 与实测口径
6 × Total Parameters（全部参数量）只是在特定稠密矩阵计算口径下的近似，还需要考虑 Attention 等计算。MoE（Mixture of Experts，混合专家）每个 token 通常只激活部分专家；共享层、路由、激活专家、序列长度与反向计算都影响实际理论模型工作量，不能拿全部专家参数直接精确计算训练 FLOPs。
Model FLOPs（模型所需运算）与硬件实际执行 FLOPs 不相同。激活重计算会重复前向以节省内存，在常见 MFU 定义中不加入模型所需前向 + 反向的分子，但会增加实际用时。不同报告必须对齐这些口径、精度、设备数与测量时间范围。
MFU 超过 100% 时先检查单位、单卡 / 全设备吞吐量、精度、Dense / Sparse 与 FLOPs 计数；本工具展示原始比例并提示检查，不把结果强行截断。
