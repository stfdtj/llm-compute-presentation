1. Convention and execution counts

Historical snapshot: sections 1-17 predate kernel verification. Their estimates
are retained as the baseline; sections 18-22 supersede the missing-kernel claims.

Y = XW; X=[M,K], W=[K,N], Y=[M,N].
Approximate GEMM = 2MKN; exact dot-product arithmetic would be MN(2K-1).
Weight shapes below use [input,output]; PyTorch stores their transpose.
B=1, T=1, S=1024 historical tokens EXCLUDING the current token.
start_pos=S; N=S+1=1025 visible tokens including the current token.
All layer IDs are zero-based. Count logical whole-model work at world_size=1.
Reuse existing window KV, compressed KV and Index Keys; do not project history.

B = source-verifiable multiply/add FLOPs (GEMMs use the requested 2MKN rule).
E = additional simplified special-operation or external-kernel estimates.
Add/subtract/multiply = 1 each. A length-d reduction = d-1 adds.
Mean = reduction plus one division. Division, rsqrt, sqrt, exp, softplus,
and sigmoid each count as 1 E operation; their real instruction costs differ.
SiLU = one sigmoid (E) plus one multiply (B); do not expand sigmoid again.
Comparisons, max/top-k, integer hashes/indexing, abs/sign operations, casts,
quantization, memory copies and communication are separate from these totals.
RoPE sin/cos are precomputed; ignore views and Python shape/constant arithmetic.
Explicit Engram dequantization multiplies ARE included, separately identified.

Layers 0-1: local only, 2 layers.
Layers 2-19: ratio-2 compressed + local, 18 layers.
Layers 20-39: ratio-1 compressed + local, 20 layers.
Window length L(S)=min(128,S+1).
C2(S)=floor((S+1)/2); C1(S)=S+1.
b(S)=1 if (S+1) is even, otherwise 0 (ratio-2 group completion).
At S=1024: L=128, C2=512, C1=1025, b=0.
Compressor owners: 2/8/14 (ratio 2), 20 (ratio 1): 4 calls.
New compressed latents / Index Keys: J(S)=3*b+1; here J=1, NOT 4.
Indexers: 2/8/14/20/24/28/32/36: 8 calls when C2>0.
HC: 2*40=80 instances, plus one final pre-collapse.
MoE: 40 routers, 240 routed-expert calls, 40 shared-expert calls.
Engram: layers 1 and 14 only, 2 calls.

Source caveat: Indexer.forward only republishes its key cache when a new latent
exists. On this b=0 step, layers 2/8/14 can read the previous layer-20 cache.
Shapes/FLOPs below still hold. Here all 512 ratio-2 positions are selected,
so this issue does not alter their selected index sets. See the audit.

18. Current counting rules and evidence labels

The source is DeepSeek-V4.1-Flash/{config.json,model.py,engram.py,kernel.py}.
No separate inference/kernel.py or training implementation was found locally.
This analysis does not claim to have reviewed a separate official trainer.

Source Verified (SV): operation/shapes/control flow are present in local source.
Mathematical Estimate (ME): 2MKN, reduction arithmetic, unit-cost special ops,
or an explicitly specified mathematical algorithm; not a measured GPU count.
Assumption (A): a proposed training-forward execution choice, not source fact.
Unknown (U): actual training code, compiler/hardware lowering, or a cost not
quantified in this report. Unknown never means zero.

Use FB=Basic FLOPs; FE=Special Operations Estimate; FM=FB+FE.
In the training section B means Batch Size, not Basic FLOPs.
GEMM FB=2MKN, including its multiply/add accumulation; do not add the same
accumulation again. Add/subtract/multiply each cost 1. A k-term sum has k-1 adds.
Division, sqrt, rsqrt, exp and sigmoid each cost 1 FE operation. Softplus also
costs 1 FE operation, without additionally counting its internal exp/log.
Fused SiLU counts sigmoid in FE and its multiply in FB. Sigmoid in the HC
kernel is counted once per call, without expanding it a second time.
A mean counts reduction in FB and one division in FE, even at constant divisor.
No reassociation, denominator hoisting or identity simplification is assumed
in the literal kernel-expression ledger. GEMM remains the requested 2MKN model.

Views/reshape/transpose contribute 0 arithmetic; copies they may induce are
memory work. Casts, clamp/max comparisons, sign/abs, top-k, sorting, indexing,
integer hashes, dispatch and communication are outside FB/FE. Memory traffic
and latency are not FLOPs. Quantization arithmetic is discussed separately in
section 22; it is excluded from the core totals, except the explicitly counted
Engram table-dequantization multiplies. Full hardware instruction totals remain U.
Thus evidence status and FB/FE are different concepts: an attention GEMM belongs
to FB even if its FLOPs are a mathematical estimate of source-verifiable work.
The old section 17 put all attention into E; the CURRENT tables correct that.

19.1 hc_split_sinkhorn

19.2 sparse_attn
Source: kernel.py:311-403; model.py:765-789.
Q=[B,T,a,D], KV=[B,Nkv,D], indices=[B,T,Klist], sink=[a], output=[B,T,a,D].
a=64 heads, D=512; no head padding because a>=16. There is no separate V.
The wrapper gathers indices in tiles q=64. Let n=ceil(Klist/64).
Invalid indices and final partial-tile slots load zero KV and start at -inf
scores. BOTH GEMMs still execute on the full 64-position tile. Max/masks do
not skip these GEMMs. Source tensors for Q/KV and probability tiles are BF16;
FP4 fake quantization earlier writes dequantized values back before this call.

For each tile, per head:
  QK GEMM: 2*q*D FB; multiply scores by 1/sqrt(D): q FB.
  Find a running maximum: comparisons only.
  alpha=exp(previous_max-new_max): 1 FB +1 FE.
  p=exp(score-new_max): q FB +q FE.
  tile_sum=sum(p): q-1 FB.
  running_sum=running_sum*alpha+tile_sum: 2 FB.
  output_accumulator*=alpha: D FB (including the first zero accumulator).
  output_accumulator+=p*KV GEMM: 2*q*D FB.
After all tiles, per head:
  running_sum+=exp(sink-running_max): 2 FB +1 FE.
  output_accumulator/=running_sum: D FE.
Sink contributes only to the denominator, not an extra value vector/GEMM.
Unlike the old reference softmax, the running maximum excludes the sink, which
is exponentiated at the end. This is mathematically equivalent for finite,
well-behaved scores, but can have different numerical overflow behavior.

Per query, all heads:
A_B(n)=a*[n*(4*q*D+3*q+2+D)+2].
A_E(n)=a*[n*(q+1)+D+1].
A_M(n)=A_B(n)+A_E(n).
This accounts for online output rescaling and final D output divisions;
it does NOT divide each stored attention probability by its sum.
It is a literal tile-algorithm estimate, not a profiler measurement.

20. Training Forward FLOPs Calculation

20.1 Scope and variables

ACTUAL DEEPSEEK TRAINING FORWARD TOTAL: Unknown from the available files.
The local Transformer.forward uses inference_mode, stateful cache buffers,
and last-position-only logits. No official training entry point, distributed
training policy or training attention kernel is supplied. Comments saying
"matching training" verify only what those comments describe, not a trainer.

We calculate Scenario P: a complete text-backbone forward mathematical model
using the source's full-sequence/prefill graph and supplied sparse kernel,
with ALL-token LM logits. This is an explicit training-forward proxy (A).
It is not incremental decode and does not reuse old tokens from a prior pass.
Fresh activations/keys are computed for every batch and every training step.
Within the SAME forward, source-layer compressed KV/Index results are shared
with later layers exactly as in local source. Such sharing does not skip
creating the source activations and does not imply detaching gradients.

Assumptions: independent dense sequences, no padding tokens/packing, no token
or expert dropping, six selected experts per token plus one shared expert,
no activation checkpoint replay, no draft/vision/sampling/loss computation,
no input prefix cache. Full LM logits for all T positions, even though the
unmodified wrapper defaults to only the last. No model implementation is changed.
Use sufficient buffer capacities for B,T: local runtime defaults are max batch
4 and max sequence 4096; formulas beyond these require larger allocations.
T is the number of tokens actually forwarded, not the number of loss targets.

L=40 layers; a=64 attention heads; D=512 head width; p=64 rotary width.
R=1280 query rank; G=8 output groups; O=1024 output rank per group.
c=4 HC copies; z=c*(c+2)=24 HC coefficients; I=20 Sinkhorn iterations.

22. Remaining costs, uncertainty, and source map

Quantization has arithmetic and is NOT free. It is a separately excluded cost
category, not classified as "non-FLOP" in its entirety. The new source reveals:
- act_quant_kernel: absmax/clamp comparisons, scale creation, element divisions,
  casts, and an extra multiply per element for inplace quantize/dequantize.
  For logical Mq-by-Nq FP8 data with groups g: scale FB=Mq*Nq/g,
  FE=Mq*Nq divisions; inplace adds Mq*Nq FB. Bit-based rounding is integer work.
- fp4_quant_kernel: analogous per-element divisions/inplace multiplies.
  E8M0 scales use one multiply per group before bit manipulation;
  compressed-KV E4M3 scales use one division per group instead.
- Quantizers tile 32 rows, so device work may also cover padded rows.
- fp8_gemm_kernel and fp4_gemm_kernel accumulate each K-block result using
  C_accum += C_block*scale_a*scale_b: 3 extra FB per output per K block.
  These are beyond the semantic projection GEMM's 2MKN and are not silently
  folded into that formula. With K-block=32, logical scale work is 3*M*N*(K/32).
  Literal dense tiles are M'=32*ceil(M/32), N'=128*ceil(N/128),
  K'=32*ceil(K/32); GEMM tile math is 2*M'*N'*K', plus 3*M'*N'*(K'/32)
  scale arithmetic. These physical-padding formulas are NOT added to the
  standard model FLOPs tables. Actual lowering still requires compiled analysis.
- Expert M is m_j, which depends on routing; summing ceil(m_j/32) cannot be
  inferred from B,T alone. Thus a full device-kernel number is not fixed by
  the architecture even though logical expert 2MKN is fixed by e*B*T.

Explicit Engram memory dequantization is already in FB; do not add it again.
Memory gathers/copies/cache writes, reductions' comparisons, RNG, top-k,
expert dispatch and network collectives remain separately unquantified.
These exclusions apply to BOTH Decode and Scenario P, consistently.
HC and sparse attention mathematical algorithms are now known; the official
training path, compiler transformations and full device costs are not.
