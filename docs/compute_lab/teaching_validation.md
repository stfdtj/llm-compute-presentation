## 官方硬件口径

- [NVIDIA H100 产品规格](https://www.nvidia.com/en-us/data-center/h100/) 的 SXM 列：80GB，HBM 带宽 3.35 TB/s。BFLOAT16 Tensor Core 1,979 TFLOP/s 带 `With sparsity` 注脚，是稀疏口径。
- [NVIDIA 官方 recsys-examples 基准说明 §2](https://github.com/NVIDIA/recsys-examples/blob/main/examples/hstu/training/benchmark/E2E_BENCHMARK.md) 明确采用 H100 的 989 BF16 Dense Tensor Core TFLOP/s。
- 本页预设：H100 SXM 80GB、BF16 Dense 989 TFLOP/s、3.35 TB/s、默认 1 张。没有拿 1,979 当作 Dense 峰值，也没有使用 NVL 的 94GB / 3.9 TB/s 数据。公开峰值为取整数值，不声称精确倍数关系。
- 带宽按十进制单位换算：3.35 TB/s = 3350 GB/s = 3.35 × 10¹² B/s。
- 修改峰值、带宽、型号或精度后，预设标记自动变为自定义；带宽 / 算力加倍按钮明确显示为教学假设。切回 H100 自动填入全部必要值，并把 Attention 的计算精度设为 BF16。
- 本轮未提供 Ascend 完整型号模板；没有同时核验型号、精度、Dense 峰值与 HBM 带宽的规格不会内置为预设。

## 默认 Roofline 数值

Attention 默认输入不变：D=4096、H=32、Hkv=8、dk=dv=128、初始历史 S=8192、连续生成 G=1024、Batch=1、BF16、计入明示标量运算。默认选择 GQA，范围为单层、整批、声明的模块范围。

以下访存均是**假设模型估算**，不是实际 HBM 测量。每步读取投影权重、历史 KV 无片上命中、头间理想共享、score / probability 片上融合；当前 KV 写入缓存。FFN、全模型其他层、通信、启动、对齐等不在此范围。

| 项目 | GQA 默认值 / 代入 |
|---|---|
| Attention FLOPs | 233,362,735,104 |
| HBM Bytes Moved | 122,425,442,304 B |
| AI | 233,362,735,104 ÷ 122,425,442,304 ≈ 1.906162 FLOPs/B |
| 总峰值 | 1 × 989 × 10¹² = 9.89 × 10¹⁴ FLOP/s |
| 总带宽 | 1 × 3.35 × 10¹² B/s |
| Ridge | 989 ÷ 3.35 ≈ 295.223881 FLOPs/B |
| 带宽性能上限 | AI × BW ≈ 6.385643 TFLOP/s |
| Roofline 上界 | min(989, 6.385643) = 6.385643 TFLOP/s |
| 瓶颈 | AI < Ridge，因此当前假设下为 Memory-bound |
| 计算时间下界 | F ÷ P_peak ≈ 0.235958 ms |
| 搬运时间下界 | M ÷ BW ≈ 36.544908 ms |
| 合并时间下界 | max(计算，搬运) ≈ 36.544908 ms |

上述总搬运量可以大于显存容量，因为连续生成过程中相同数据会重复读取；它不是一次驻留容量。图上的点位于理论屋顶，不能解释为实测点。合并区间下界可能比各步下界之和更宽松。

独立手算测试使用可见历史 8193…9216，总和 8,913,408：

```text
F_GQA = 83,886,080 × 1024 + 16,544 × 8,913,408 − 32 × 1024
Bytes = 83,886,080 × 1024 + 4096 × (8,913,408 − 1024)
        + 4,194,304（缓存写入）+ 16,777,216（输入输出）
```

带宽 ×2 后，当前 GQA 的计算密度不变，带宽上界翻倍，时间下界减半；算力 ×2 后，仍由搬运限制，上界不变。实际程序未必达到这些理想变化。多设备只支持独立批序列均分，不建模张量并行。

## MFU 假设示例

定义参考 [PaLM §4.1 与 Appendix B](https://arxiv.org/html/2204.02311v5#S4.SS1)：模型所需前向 + 反向 FLOPs 与实测训练吞吐量相结合；激活重计算不直接加入模型所需运算的分子，但其耗时会影响吞吐量。

本页全部 MFU 输入明确标记为教学假设，不代表 H100 或 Ascend 训练实测，也不读取 Decode 计算量：

```text
Training FLOPs/token = 1 × 10¹²（包含前向 + 反向）
全设备 Tokens/s = 2000
设备数 = 4；单设备峰值 = 1000 TFLOP/s（假设同一精度的 Dense 峰值）
模型 FLOP/s = 1 × 10¹² × 2000 = 2 × 10¹⁵
全部硬件峰值 = 4 × 1000 × 10¹² = 4 × 10¹⁵
MFU = 2 / 4 = 50%
```

另一输入方式：8000 Tokens/Step ÷ 4 秒 = 全设备 2000 Tokens/s；时间变为 8 秒时，MFU 为 25%。计算量减半、吞吐量翻倍，MFU 保持 50%；计算量减半、吞吐量只增 50%，MFU 变为 37.5%。超过 100% 的假设结果保留原始比例并提示核对口径。训练导入格式接口独立保留，不覆盖教学假设。
